# 📝 Blog — Тестовое задание

Простой, но полностью функциональный блог на чистом PHP 8.1+ с использованием MySQL и шаблонизатора Smarty. Проект реализует классический функционал блога с категориями, статьями, сортировкой, пагинацией и рекомендациями похожих материалов.

---

## 🛠 Технологический стек

| Компонент | Технология |
|---|---|
| Backend | PHP 8.1+ (без фреймворков) |
| База данных | MySQL 8.0 |
| Шаблонизатор | Smarty 4.x |
| Стили | SCSS |
| Контейнеризация | Docker + docker-compose |
| Управление зависимостями | Composer (PHP), npm (SCSS) |
| Генерация тестовых данных | FakerPHP |

---

## ✨ Возможности

### Основной функционал
- 🏠 **Главная страница** — список категорий с 3 последними постами в каждой
- 📂 **Страница категории** — список статей с сортировкой (по дате / по просмотрам) и пагинацией
- 📄 **Страница статьи** — полный текст, метаданные, список категорий
- 🔗 **Похожие статьи** — блок из 3 рекомендаций на основе общих категорий
- 📊 **Счётчик просмотров** — автоматический инкремент при открытии статьи
- 🌱 **Сидер** — CLI-скрипт для наполнения БД тестовыми данными

### Технические особенности
- ЧПУ-ссылки (`/category/tehnologii`, `/post/moi-pervyi-post`)
- Защита от SQL-инъекций (PDO + prepared statements)
- Оптимизация N+1 запросов на главной через `ROW_NUMBER()`
- Транзакции при работе со связями Many-to-Many
- Автоэкранирование вывода в Smarty (защита от XSS)
- Валидация GET-параметров (белый список для `sort`)

## 🚀 Установка и запуск

### 1. Клонировать репозиторий

```bash
git clone <repository-url> blog
cd blog
```

### 2. Настроить переменные окружения

```bash
cp .env.example .env
```

Дефолтные значения уже подходят для разработки.

### 3. Запустить контейнеры

```bash
docker-compose up -d --build
```

### 4. Установить зависимости PHP

```bash
docker-compose exec php composer install
```

### 5. Установить зависимости Node.js (для SCSS)

```bash
docker-compose run --rm node npm install
```

### 6. Настроить права на папку storage

```bash
docker-compose exec php chmod -R 777 storage/
```

### 7. Выполнить миграции

```bash
docker-compose exec php php bin/migrate.php
```

### 8. Наполнить БД тестовыми данными

```bash
docker-compose exec php php bin/seed.php
```

### 9. Скомпилировать SCSS

```bash
docker-compose run --rm node npm run build
```

### 10. Открыть в браузере

👉 **http://localhost:8080**

## 🗺 Маршруты

| URL | Описание |
|---|---|
| `/` | Главная страница |
| `/category/{slug}` | Страница категории |
| `/post/{slug}` | Страница статьи |

### Параметры запросов

**Страница категории:**
- `?sort=date` — сортировка по дате (по умолчанию)
- `?sort=views` — сортировка по просмотрам
- `?page=2` — номер страницы

docker-compose down

# Остановить и удалить все данные (включая БД)
docker-compose down -v
```

## 🏗 Архитектурные решения

### 1. MVC-подобная структура
Несмотря на отсутствие фреймворка, код организован по принципам MVC:
- **Models** — работа с БД и бизнес-логика
- **Controllers** — обработка запросов, вызов моделей, передача данных в шаблоны
- **Views (Smarty)** — только отображение

### 2. Оптимизация N+1 на главной
Вместо N запросов (по одному на категорию) используется один запрос с оконной функцией `ROW_NUMBER() OVER (PARTITION BY category_id)`, который выбирает по 3 последних поста для каждой категории. Результат группируется в PHP.

### 3. Безопасность
- **SQL-инъекции:** PDO + prepared statements, `EMULATE_PREPARES = false`
- **XSS:** Smarty по умолчанию экранирует все переменные; в критичных местах добавлен модификатор `|escape`
- **Инъекции в ORDER BY:** белый список через `match` (нельзя биндить имена столбцов)
- **Валидация GET-параметров:** проверка допустимых значений `sort`

### 4. Кодировка UTF-8
Полная поддержка UTF-8 на всех уровнях:
- Таблицы: `utf8mb4_unicode_ci`
- PDO: `charset=utf8mb4` + `SET NAMES utf8mb4`
- HTML: `<meta charset="UTF-8">`

### 5. Many-to-Many связь
Статья может принадлежать нескольким категориям через связующую таблицу `post_categories` с составным первичным ключом и каскадным удалением.

## 🔮 Возможные улучшения

Если бы проект развивался дальше, я бы добавил:

1. **Кэширование счётчика просмотров** — запись в Redis и батч-обновление в MySQL раз в минуту, чтобы избежать блокировок при высокой нагрузке
2. **Полнотекстовый поиск** — `FULLTEXT` индекс на `title` и `content` или интеграция с Elasticsearch
3. **Админ-панель** — CRUD для статей и категорий с загрузкой изображений
4. **Комментарии** — с модерацией и anti-spam
5. **Теги** — ещё одна сущность Many-to-Many для более гибкой категоризации
6. **RSS-лента** — для подписки на обновления
7. **Unit-тесты** — PHPUnit для моделей и контроллеров
8. **CI/CD** — GitHub Actions для автопроверки PR
9. **Rate limiting** — защита от злоупотреблений счётчиком просмотров
10. **Миграционная система** — полноценный трекер миграций (как в Laravel) с таблицей `migrations`
